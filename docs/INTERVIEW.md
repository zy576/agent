# 面试答辩速记

## 为什么这不是现成 Agent 的封装？

唯一远程调用是普通 Chat Completions。`CodingAgent` 自己保存消息、配对 `tool_call_id`、执行本地函数、把结果回传并决定何时停止；`ContextManager`、`ToolRegistry` 和重试逻辑也都在仓库中。

## 模型怎样“选择”工具？

程序把六个函数的 JSON Schema 随消息发送。模型返回函数名和 JSON 字符串参数，程序解析、校验并本地执行；模型看不到可直接控制的终端或文件系统。

## 为什么不用 shell 字符串？

普通可执行文件通过 `argv` 直接传给 `subprocess`，不解释管道和重定向。Windows 的 npm 等 `.cmd/.bat` 启动器会先通过 PATH 解析为绝对路径，并拒绝元字符参数。复杂流水线必须拆成多个进程调用。

## 坏 JSON、命令失败和网络错误怎么办？

坏 JSON、缺参、未知工具和路径策略错误都变成结构化 tool 结果，模型可修正。命令输出始终带 exit code。429/5xx 与短暂网络错误重试；4xx 参数或鉴权错误直接暴露安全错误信息，但不含 key。

## 如何判断任务完成？

模型无工具调用并给出最终报告是正常终止；但最后一次写入之后必须有一次成功命令验证。默认不设模型决策步数上限，让复杂任务持续到报告完成；相同调用重复四次、总工具调用量和总运行时间仍会硬熔断，显式传入 `--max-steps` 时也可启用有限步数模式。

## 上下文为什么不能简单删前半段？

OpenAI-compatible 协议要求 assistant `tool_calls` 与对应 tool 消息成组出现。拆开会导致 400 或语义错乱，所以压缩单位是完整工具交互组。单次模式固定 system policy 与原始任务；交互模式固定 system policy 与当前活动任务，旧轮次才允许压缩。

## 怎样支持人机交互？

`--interactive` 在同一 client、workspace 和 agent 上连续运行多轮：只有一轮正常返回后才提交其完整历史，用户下一条输入作为新 user 消息追加。每轮预算重置，但未验证修改的债务跨轮保留；`/quit` 和 `/exit` 由本地处理，不交给模型。

`--web` 是相同会话状态机的可视化适配层：左侧保留自然语言对话，右侧把 `model_request`、`tool_start`、`tool_end`、`warning` 和最终验证做成实时轨迹。浏览器从不持有原始历史或 API Key；刷新只重放后端有界事件，异常回合则安全关闭而不是猜测历史。

## 这是沙箱吗？

不是。路径校验、无 shell 子进程、超时与密钥剥离是减灾措施。任意测试程序仍可能访问宿主权限范围；强隔离必须依赖容器、虚拟机或 OS 权限机制。

## 为什么关闭 DeepSeek thinking？

V4 thinking 模式在工具多轮中要求回传 `reasoning_content`。本项目优先展示标准、可移植的原生工具循环，因此显式关闭；客户端仍保留服务端意外返回的该字段。

## 下一步如何扩展？

可增加基于哈希的乐观写入锁、容器执行后端、结构化运行日志、人工审批级别和基于真实 token usage 的动态上下文预算，但不改变当前显式状态机。
